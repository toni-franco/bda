    Instal.lació de Docker compose

    Per a instal·lar Docker Compose (el connector oficial docker-compose-plugin, que habilita l'ordre docker compose) en Debian 12 (Bookworm), el més recomanable és configurar el repositori oficial de Docker i instal·lar Docker Engine juntament amb el connector.

    Passos per a instal·lar Docker i Docker Compose en Debian 12

    1.Eliminar paquets antics o en conflicte:2 min.

    Si tens versions antigues o paquets no oficials de Docker/Compose instal·lats, elimina'ls primer per a evitar conflictes:

    for pkg in docker.io docker-doc docker-compose podman-docker containerd runc; do
  sudo apt remove -y "$pkg"
done

    Verificació: Executa apt policy docker.io i comprova que no figura com a instal·lat.

    2.Afegir la clau GPG i el repositori oficial de Docker:3 min.

    Instal·la els paquets necessaris per a apt sobre HTTPS, descarrega la clau GPG oficial de Docker i afig el repositori corresponent a bookworm:

    sudo apt update
sudo apt install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/debian $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update

    Verificació: En executar sudo apt update, hauries de veure línies apuntant a [https://download.docker.com/linux/debian](https://download.docker.com/linux/debian) bookworm InRelease sense errors de signatura.

    3.Instal·lar Docker Engine i Docker Compose plugin: 3 min.

    Instal·la el motor de Docker, la CLI, containerd, buildx i el connector de Compose:

    sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

    Verificació: Executa docker compose version i sudo systemctl status docker per a confirmar que el connector respon i el servei està actiu (active (running)).

    4.Executar Docker sense sudo (opcional però recomanat):2 min.

    Afig el teu usuari actual al grup docker per a llançar ordres docker compose sense posar sudo davant:

    sudo usermod -aG docker "$USER"
newgrp docker

    Verificació: Executa docker compose version sense sudo i comprova que torna la versió instal·lada sense errors de permisos en /var/run/docker.sock.

    Comprovació ràpida amb docker compose

    Pots verificar que tot funciona creant un directori de prova amb un fitxer compose.yaml senzill:

    mkdir -p ~/prova-compose && cd ~/prova-compose
cat << 'EOF' > compose.yaml
services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
EOF
docker compose up -d
docker compose ps

    Si obris http://localhost:8080 (o http://<IP_DEL_TEU_DEBIAN>:8080), hauries de veure la pàgina de benvinguda d'Nginx. Per a detindre'l i esborrar el contenidor, executa docker compose down.

    Guia Ràpida: Ordres Bàsiques de Docker, Dockerfile i Docker Compose

    Aquest document recull les ordres més habituals per treballar amb Docker (gestió d'imatges, contenidors, volums i xarxes), la creació d'imatges personalitzades amb Dockerfile i Docker Compose (orquestració de múltiples contenidors).

    El professor entregarà uns documents en format pdf amb els exercicis a fer les captures que es demanen

    1. Ordres Bàsiques de Docker

    Imatges (docker image)

    Les imatges són les plantilles de només lectura a partir de les quals es creen els contenidors.

    • Cercar una imatge a Docker Hub:

    bash docker search <nom_imatge>

    • Descarregar una imatge:

    bash docker pull <nom_imatge>:<etiqueta> # Exemple: docker pull ubuntu:22.04

    • Llistar les imatges descarregades al sistema:

    bash docker images

    • Construir una imatge a partir d'un Dockerfile:

    bash docker build -t <nom_imatge>:<etiqueta> .

    • Eliminar una imatge:

    bash docker rmi <id_o_nom_imatge>

    Contenidors (docker container)

    Els contenidors són instàncies en execució d'una imatge.

    • Crear i arrencar un contenidor nou:

    bash docker run -d --name <nom_contenidor> -p <port_host>:<port_contenidor> <imatge>

    • -d: Executa el contenidor en segon pla (detached mode).
    • --name: Assigna un nom personalitzat al contenidor.
    • -p: Mapeja un port de la màquina amfitriona amb un port del contenidor (ex. -p 8080:80).
    • -v: Munta un volum o carpeta local (ex. -v /ruta/local:/ruta/contenidor).
    • -e: Defineix variables d'entorn (ex. -e MYSQL_ROOT_PASSWORD=secret).

    • --rm: Elimina el contenidor automàticament quan s'atura.

    • Llistar contenidors:

    bash docker ps # Només els que estan en execució docker ps -a # Tots (en execució i aturats)

    • Aturar i arrencar contenidors existents:

    bash docker stop <nom_o_id> docker start <nom_o_id> docker restart <nom_o_id>

    • Eliminar un contenidor (ha d'estar aturat):

    bash docker rm <nom_o_id> # Per forçar l'eliminació encara que estigui en execució: docker rm -f <nom_o_id>

    Inspecció, Registres (Logs) i Execució

    Ordres per depurar i interactuar amb contenidors que ja estan en marxa.

    • Veure els registres (logs) d'un contenidor:

    bash docker logs <nom_o_id> docker logs -f <nom_o_id> # Seguir els logs en temps real

    • Obrir un terminal interactiu dins d'un contenidor en execució:

    bash docker exec -it <nom_o_id> /bin/bash # O si la imatge és molt lleugera (com Alpine): docker exec -it <nom_o_id> sh

    • Veure informació detallada (IP, volums, configuració) d'un contenidor:

    bash docker inspect <nom_o_id>

    • Veure el consum de recursos (CPU, RAM) en temps real:

    bash docker stats

    Volums i Xarxes

    Per persistir dades i comunicar contenidors entre si.

    • Gestionar Volums:

    bash docker volume ls # Llistar volums docker volume create <nom_volum> # Crear un volum docker volume rm <nom_volum> # Eliminar un volum

    • Gestionar Xarxes:

    bash docker network ls # Llistar xarxes docker network create <nom_xarxa> # Crear una xarxa docker network rm <nom_xarxa> # Eliminar una xarxa

    Neteja del Sistema

    Alliberar espai eliminant recursos que no s'utilitzen.

    • Eliminar tots els contenidors aturats, xarxes sense ús i imatges òrfenes:

    bash docker system prune

    • Neteja profunda (inclou totes les imatges no utilitzades i volums):

    bash docker system prune -a --volumes

    2. Ordres Bàsiques de Docker Compose

    Docker Compose permet definir i executar aplicacions multicontenidor mitjançant un fitxer de configuració anomenat docker-compose.yml (o compose.yaml).

    Nota: En les versions modernes de Docker, l'ordre s'escriu amb un espai (docker compose) en lloc d'un guió (docker-compose).

    Cicle de Vida de l'Aplicació

    Aquestes ordres s'han d'executar dins del directori on es troba el fitxer docker-compose.yml.

    • Crear i arrencar tots els serveis definits:

    bash docker compose up -d

    • -d: Executa els serveis en segon pla.

    • --build: Força la reconstrucció de les imatges abans d'arrencar.

    • Aturar i eliminar contenidors i xarxes creades per up:

    bash docker compose down

    • -v (o --volumes): Elimina també els volums declarats (compte: es perdran les dades!).

    • Aturar i arrencar serveis sense eliminar-los:

    bash docker compose stop docker compose start docker compose restart

    Gestió i Monitoratge de Serveis

    • Veure l'estat dels contenidors del projecte actual:

    bash docker compose ps

    • Veure els logs de tots els serveis (o d'un en concret):

    bash docker compose logs -f docker compose logs -f <nom_servei>

    • Executar una ordre dins d'un servei en execució:

    bash docker compose exec <nom_servei> /bin/bash

    • Construir o reconstruir les imatges dels serveis:

    bash docker compose build

    • Descarregar les últimes versions de les imatges del fitxer:

    bash docker compose pull

    Pràctica utilitzan la imatge d'Ubuntu

    Aquí tens el tutorial actualitzat incorporant exemples pràctics que utilitzen la imatge d'Ubuntu (ubuntu:24.04 / ubuntu:latest), tant en l'execució de contenidors, la creació d'imatges amb Dockerfile com en la configuració amb Docker Compose

    1. Ordres Bàsiques amb la Imatge d'Ubuntu

    Executar i gestionar contenidors Ubuntu

    • Descarregar la imatge oficial d'Ubuntu:
    docker pull ubuntu:24.04
    • Executar un contenidor interactiu d'Ubuntu amb terminal (bash) i esborrar-lo en sortir:
    docker run -it --rm --name meu_ubuntu ubuntu:24.04 /bin/bash
    • -it: Combina -i (entrada interactiva) i -t (pseudo-TTY) per treballar dins del terminal.
    • --rm: Elimina automàticament el contenidor quan s'atura (ideal per fer proves ràpides).

    • --name meu_ubuntu: Assigna un nom fàcil d'identificar al contenidor.

      Captura pantalla (fitxer: UP2-E01-15-02.png) executant la ordre: pwd;id;cat /etc/lsb-release

    • Executar un contenidor Ubuntu en segon pla (detached) perquè es mantingui actiu:

    docker run -d --name ubuntu_bg ubuntu:24.04 sleep infinity
    • Sense un procés actiu en primer pla (com sleep infinity), un contenidor base d'Ubuntu s'aturaria just després d'arrencar.
    • Obrir una nova sessió interactiva dins del contenidor en execució:
    docker exec -it ubuntu_bg /bin/bash

    • Un cop dins d'Ubuntu, pots fer servir les ordres habituals del sistema, com ara: apt update && apt install -y curl.

      Captura pantalla. Fitxer: UP2-E01-15-03.png

    • Inspeccionar, veure logs i aturar/eliminar el contenidor:

    docker inspect ubuntu_bg
docker logs -f ubuntu_bg
docker stop ubuntu_bg
docker rm ubuntu_bg

    Captura. Fitxer: UP2-E01-15-04.png

    Volums i xarxes amb Ubuntu

    • Muntar un volum per persistir dades creades dins d'Ubuntu:
    docker volume create dades_ubuntu
docker run -it --rm -v dades_ubuntu:/dades ubuntu:24.04 /bin/bash

    2. Creació d'Imatges amb Dockerfile (Basades en Ubuntu)

    Un Dockerfile permet automatitzar la creació d'una imatge personalitzada a partir d'Ubuntu.

    Instruccions principals

    • FROM: Defineix la imatge base (per exemple, ubuntu:24.04).
    • WORKDIR: Estableix el directori de treball dins del contenidor.
    • COPY: Copia fitxers o directoris des de la màquina local cap al contenidor.
    • RUN: Executa ordres durant la construcció de la imatge (com apt-get update i instal·lació de paquets).
    • ENV: Defineix variables d'entorn persistents (per exemple, DEBIAN_FRONTEND=noninteractive per evitar prompts interactius d'apt).
    • EXPOSE: Documenta el port d'escolta de l'aplicació.
    • CMD: Defineix l'ordre per defecte en arrencar el contenidor.

    Exemple 1: Entorn Ubuntu amb Python i eines bàsiques

    Crea los ficheros:

    #Requeriments.txt
# Versión exacta
requests==2.32.3

# Rango compatible (permite actualizaciones de parche/menores según la regla de pip)
flask~=3.0.0

# Cualquier versión más reciente disponible
python-dotenv

    Fitxer: app.py

    from flask import Flask

app = Flask(__name__)


@app.route("/")
def hola_mundo():
  return "¡Hola, mundo desde Python web!"


if __name__ == "__main__":
  app.run(host="0.0.0.0", port=5000, debug=True)



    FROM ubuntu:24.04

# Evita preguntes interactives durant la instal·lació de paquets amb apt
ENV DEBIAN_FRONTEND=noninteractive
ENV PYTHONUNBUFFERED=1
ENV FLASK_APP=app.py
ENV FLASK_RUN_HOST=0.0.0.0

WORKDIR /app

# Actualitzar repositoris, instal·lar Python i netejar la cau d'apt per reduir mida
RUN apt-get update && apt-get install -y --no-install-recommends \
    python3 \
    python3-pip \
    curl \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip3 install --no-cache-dir --break-system-packages -r requirements.txt

COPY app.py .

EXPOSE 5000

#CMD ["python3", "-m", "http.server", "8000"]
CMD ["python3", "app.py"]

    docker build -t meua_imatge:v1 .

    docker run -it -p 5000:5000 --name meu_contenidor meua_imatge:v1

    3. Ordres Bàsiques de Docker Compose

    Executa aquestes ordres des del directori on es troba el fitxer docker-compose.yml:

    docker compose up -d --build   # Construeix (si cal) i arrenca els serveis en segon pla
docker compose ps              # Consulta l'estat dels contenidors
docker compose logs -f         # Segueix els logs en temps real
docker compose exec ubuntu_dev /bin/bash  # Entra al terminal del servei ubuntu_dev
docker compose stop            # Atura els serveis sense esborrar contenidors
docker compose down            # Atura i elimina contenidors i xarxes creades
docker compose down -v         # Elimina també els volums declarats (atenció: pèrdua de dades)

    4. Exemple Pràctic de docker-compose.yml amb Ubuntu
